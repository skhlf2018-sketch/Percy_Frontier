## 3. 알려진 한계

- 렌더링은 이 개발 환경의 소프트웨어 Vulkan(llvmpipe)과 OpenGL에서만 확인했습니다. 실제 GPU가 있는 Windows PC에서의 화면·성능은 아직 확인하지 않았습니다.
- Windows 빌드(`tools/export.sh`)는 이 환경에서 직접 실행할 수 없어, 같은 게임 데이터를 담은 Linux 배포용 빌드로 대신 점검했습니다(배포용 엔진에서 전체 불러오기와 자동 플레이, 가상 화면에서 실제 입력으로 입장·이동·사격).
- 성능은 렌더링을 뺀 스크립트·물리 비용만 측정했습니다(적 23마리 동시 교전 시 프레임당 약 2ms).
- 돌격수(반지름 약 1m)도 작은 적과 같은 내비게이션 메시(반지름 0.5m)를 써서, 좁은 틈에서 모서리에 걸릴 수 있습니다.
- 1인칭 모델·적 모델·애니메이션·효과음은 모두 임시입니다(기본 도형과 절차 애니메이션, 합성음).
- 시험 단말기의 "모든 몬스터 분석 완료"는 시험장 전용 기능이며 정식 게임에는 넣지 않습니다.

## 4. 사람이 직접 확인해야 하는 것 (기획서 §26.1 전투 승인)

자동 테스트로는 판단할 수 없는 항목입니다. 다음 단계로 넘어가기 전에 플레이로 확인이 필요합니다.

- 각 무기군의 차이를 음향과 리듬으로 구분할 수 있는가
- 약점·장갑·일반 명중을 즉시 구분할 수 있는가
- 총기·근접·스킬을 섞어 쓸 이유가 실제 전투에서 생기는가
- 사망 원인을 이해할 수 있는가
- 난이도가 높은 HP가 아니라 패턴 학습에서 오는가
